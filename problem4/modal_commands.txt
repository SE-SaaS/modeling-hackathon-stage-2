==========================================================================
 STEP 0 — LOCAL, ONCE EVER (not per workspace)
==========================================================================
# Generates the 9 experiment folders on THIS disk. Touches nothing on Modal.
# Only re-run it after editing _make_experiments.py. Existing config.yaml kept.
python problem4/training_scripts/_make_experiments.py

# The whole training_scripts/ tree is shipped into the container by
# add_local_dir at `modal run` time, so every workspace automatically gets
# whatever is on your disk right now. Nothing to sync manually.


==========================================================================
 STEP 1 — PER WORKSPACE, ONCE EACH
 Repeat this whole block for every workspace you intend to launch from.
 Volumes are per-workspace: workspace B cannot see workspace A's data.
==========================================================================

# 1a. select the workspace FIRST. Everything below lands in whichever
#     workspace is active, so getting this wrong creates volumes in the
#     wrong account and the runs then fail to find /data.
$env:MODAL_CONFIG_PATH = "$HOME\.modal_session1.toml"
modal setup                 # only the first time this config file is used
modal profile list          # confirm the active workspace before continuing

# 1b. create the two volumes
modal volume create tiny-data
modal volume create tiny-runs

# 1c. upload the dataset (~5200 files / 2.4 GB, a few minutes)
#     The remote layout must end up as:
#       /data/dataset_release/{train,val}/{images,labels}
modal volume put tiny-data "C:\Users\mamou\Downloads\too-small-to-handle\dataset_release\dataset_release" /dataset_release

# 1d. sanity-check the layout BEFORE launching anything. If train/ is not
#     directly under /dataset_release, the runs will fail on a missing path.
modal volume ls tiny-data /dataset_release
modal volume ls tiny-data /dataset_release/train


==========================================================================
 STEP 2 — RUN THE EXPERIMENTS
 All 9 are independent; launch them in separate terminals and they run in
 parallel. Each builds its dataset on first use and caches it at
 /runs/_datasets/<cache_key>, so runs sharing a cache_key reuse the build.
 Launch ONE of each cache_key first to avoid duplicate builds; otherwise
 just fire them all, the cost is a couple of minutes each.

 Splitting across workspaces: every terminal must set MODAL_CONFIG_PATH to
 the workspace it is launching into, and that workspace must already have
 completed STEP 1. Runs in different workspaces share nothing — including
 the dataset cache, which each one rebuilds.
==========================================================================

# --- LIGHTS: input size sweep (the score lives here) ---
# 3 tiles of the 0.30-0.90 band. A 12px light becomes 12 * imgsz/912 px.
1-  modal run problem4/training_scripts/lights_t640/train.py            # 8.4 px light
2-  modal run problem4/training_scripts/lights_t768/train.py            # 10.1 px light
3-  modal run problem4/training_scripts/lights_t896/train.py            # 11.8 px light

# --- LIGHTS: one-variable variants, all against lights_t768 ---
4-  modal run problem4/training_scripts/lights_t768_p2/train.py         # stride-4 head
5-  modal run problem4/training_scripts/lights_t768_yellow4/train.py    # yellow x4
6-  modal run problem4/training_scripts/lights_t768_wideband/train.py   # band 0.20-0.95

# --- SIGNS ---
7-  modal run problem4/training_scripts/signs_640/train.py
8-  modal run problem4/training_scripts/signs_640_aug/train.py
9-  modal run problem4/training_scripts/signs_960/train.py
